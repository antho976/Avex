# Train: set logging components

Scope: the live session's exercise card, set input row, set rows, rest timer (inline, bubble, controls dialog), swap picker, add-exercise sheet, chart sheet, effort rater and session summary (`ui/gym/train/components/`, plus the handlers and builders they call). 18 raised, 18 kept (10 revised), 0 dropped.

The visuals are well hardened: units, stones precision, plate counts and 200% reflow all hold. The debt is in the logging loop. Freestyle already handles several things this screen doesn't: it carries the set just logged into the next set, offers Undo on delete, lets a hold be edited and tags sets. Several engine features are built but have no surface the lifter can tap: the suggested load, plate math, the later-lift warm-up ladder, set tags and last session's note. The rest is colour and alpha drift on the readings a lifter checks mid-set. SETTLED lists the live-session screen as **untouchable** ([SETTLED.md:138](../../../.claude/design/SETTLED.md#L138), and COACH_V3_PLAN says in-session surfaces need a design decision first), so every item below needs Antho's sign-off. None of them restructures the screen.

## Findings

### TRL-01 · A weight change on set 1 snaps back to last session's weight on every later set
ux-friction · impact high · effort S · Live session > exercise card > set input row

- **Now:** The weight and reps fields re-seed for each new set from `priorSetForActiveRow`, which is last session's set at the same position ([ExerciseCard.kt:363](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/ExerciseCard.kt#L363)). When that set doesn't exist, they fall back to `prefillWeight`, which is last session's FIRST set ([SetInputRow.kt:132](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SetInputRow.kt#L132), [DayViewModelBuilders.kt:219](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/DayViewModelBuilders.kt#L219)). The set just logged this session is used only by the hold-LOG-SET repeat gesture ([ExerciseCard.kt:353](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/ExerciseCard.kt#L353), caption at [SetInputRow.kt:590](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SetInputRow.kt#L590)), and that gesture copies weight AND reps. On an exercise you've never done, the weight field comes back blank on every set. Freestyle seeds from the set just logged ([FreestyleLogModel.kt:124](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogModel.kt#L124)).
- **Why it matters:** Adding load is the act the app exists to cause, and right now it costs the most. Go from 100 to 105 on set 1, then get 8, 7, 7 reps: sets 2 and 3 come back at 100. You either step the weight up again on every set, or tap LOG SET from habit and quietly log the old weight. Hold-to-repeat only helps when the reps match exactly.
- **Proposal:** Pass `lastLogged` into `SetInputRow` and carry today's change forward. If the previous set was logged at last session's weight for that position, keep the current seed. If it was changed, seed = `prior[pos].weight + (today[pos-1].weight − prior[pos-1].weight)`, which keeps pyramids and back-off sets in shape. If `prior[pos]` is missing, seed = `today[pos-1].weight`. Leave the reps seed as it is. Re-point the `untouchedSeedOrTyped` stones/kg guard at whichever set supplied the seed. Unit-test straight sets, a pyramid and a first-time exercise.
- **Doctrine:** §13 (hot-path numbers are steppers plus inline edit): this removes edits. The seed is still the user's own numbers, which is the reason the code gives for not seeding the plan target. No element is added, so the untouchable screen keeps its shape. It follows freestyle's intent ("a straight set is one tap", MAP FREESTYLE_LOG), adapted to a screen that also has per-position history.

### TRL-04 · Swiping a logged set away deletes it permanently, with no Undo
ux-friction · impact high · effort S · Live session > set row swipe-to-delete

- **Now:** A left swipe past the threshold calls `onDelete` straight away ([SetRow.kt:270](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SetRow.kt#L270)). The red background appears only once the threshold is crossed ([SetRow.kt:471](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SetRow.kt#L471)). `DeleteSet` removes the row, cancels the rest and drops the suggestion sample, and offers no Undo ([DayExerciseHandlers.kt:32](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/DayExerciseHandlers.kt#L32)). Freestyle shows `Set N removed · Undo` ([FreestyleLogScreen.kt:252](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogScreen.kt#L252)). No prior audit tracks this.
- **Why it matters:** A sideways drag with a sweaty thumb on a scrolling card loses a set for good, along with its RPE and possibly the session's PR star. Freestyle lets you undo the same act, so the app teaches two opposite expectations.
- **Proposal:** Capture the `LoggedSet` before deleting. Then call `SnackbarController.showUndo("Set 3 removed") { restore }` with freestyle's wording. Add `WorkoutRepository.restoreSet(set)`, a plain `loggedSetDao.insert` of the captured row with its id, index, rpe, `completedAt`, duration and tags, followed by `refreshExercise`. On undo, put back the suggestion-outcome sample if the set carried one. Skip the restore if the session has finished in the meantime.
- **Doctrine:** §12 says undo over confirm. §8 makes `SnackbarController` the app's one Undo snackbar, so this uses it rather than the screen's private `SnackbarHostState` (the prior audit already flags that host, [01-gym-train.md](../2026-09-26/01-gym-train.md)). No confirm dialog is added.

### TRL-03 · Effort is asked for after the workout but hidden during it
discoverability · impact high · effort M · Live session > set rows, card footer, session summary

- **Now:** The only way to set per-set RPE is to tap a `—` drawn at muted@0.35 inside a pill with 4dp vertical padding, after the set is logged ([SetRow.kt:296](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SetRow.kt#L296)). The input row's RPE column holds a dead `—` at 0.3 ([SetInputRow.kt:405](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SetInputRow.kt#L405)). The per-exercise rater sits behind a `How did it feel? ▾` toggle placed below LOG SET and MOVE TO NEXT ([ExerciseCardComponents.kt:497](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/ExerciseCardComponents.kt#L497)), and MOVE TO NEXT replaces the card. When nothing is rated, `EffortModel` reads "room to progress" ([EffortModel.kt:104](../../../forge-android/app/src/main/java/com/forge/app/domain/adapt/EffortModel.kt#L104)). The summary then shows `EFFORT 0/5 lifts · RPE 0/18 sets` and says "next time" ([SessionSummaryComponents.kt:138](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SessionSummaryComponents.kt#L138)). The watch already asks at the right moment: its rest screen offers `rate →` for the set just logged ([TimerView.kt:113](../../../forge-android/wear/src/main/java/com/forge/wear/ui/TimerView.kt#L113)).
- **Why it matters:** For most phone users the progression engine never gets its main effort signal, so loads climb as if every set was easy. The only time effort comes up is in the summary, after the workout, when it's too late to rate anything.
- **Proposal:** (1) Turn the input row's RPE cell into the same pill `SetRow` draws, optional and empty by default. Its value is written with the set (`LogSet`, then `SetRpe` on the new id). Effort is then captured as you log, the same moment the watch asks, and costs nothing to anyone who skips it. At 200% the stacked layout drops that column, so put the pill on the stacked second line, as `SetRow` already does. (2) Once `targetsMet`, draw the existing `DifficultyRater` above the advance CTA, open, not behind the ▾. Keep the footer line for re-rating. It never gates MOVE TO NEXT. See TRL-15 for one picker shared by both.
- **Doctrine:** Placement is the issue, not §4.2: a disclosure on a control is allowed (SETTLED, Cardio "More" expander). The rater is a selection group, the same weight as radio tiles, not a filled capsule, so no button wall. Nothing is gated, honouring the warm-up stepper lesson in SETTLED. No caption is added. PRODUCT principle 2: this feeds the engine the reading it already asks for.

### TRL-02 · The coach's suggested load is the one number on the card you cannot tap
ux-friction · impact medium · effort S · Live session > plan line and set input ghost

- **Now:** `try 105 lb` is an accent span inside a passive italic Text ([ExerciseCard.kt:208](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/ExerciseCard.kt#L208)). `SetInputRow` receives `suggestedWeight`, but only the unreachable legacy branch reads it. The row's one shortcut, the `beat 100 lb × 8` ghost, autofills last session's weight ([SetInputRow.kt:336](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SetInputRow.kt#L336)). That is usually the seeded value already, so tapping it changes nothing.
- **Why it matters:** Taking a progression means reading the plan line, then stepping or typing. That's one `+` tap for a 5 lb or 2.5 kg jump, and typing for anything off the stepper grid. The finder said the calibrator learns only from typed picks. That was overstated: a stepper landing on the exact target also counts as as-is. The real cost is that the screen's one tappable hint offers the old number and not the new one.
- **Proposal:** While no set this session has reached `suggestedWeight` (or `suggestedReps` on bodyweight), the existing ghost slot reads `try 105 lb`: onBg text with an accent `↑` glyph. Tapping it loads the weight only and leaves reps alone. After that, the slot goes back to `beat …`. Remove the accent span from the plan line so the cue has one home. With TRL-01 in place, set 1's choice carries to the remaining sets.
- **Doctrine:** §4.3 one home: the cue moves rather than being copied. §14 and the SETTLED open decision ban new accent-coloured text, so onBg with an accent glyph. PRODUCT, "the coach proposes, the user disposes": this loads a value and commits nothing, and the seed stays the user's own numbers. It reuses an existing tap target, so no new button.

### TRL-05 · A PR row says "record" but never shows the record it beat
missing-state · impact medium · effort S · Live session > set row PR state

- **Now:** A PR row gets a gold ★ and a gold weight ([SetRow.kt:363](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SetRow.kt#L363)), plus confetti and a TalkBack "personal record". The grey line under the weight still shows last session's set at that position ([SetRow.kt:395](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SetRow.kt#L395)), not the record that fell. `PrDetector` compares against the heaviest prior set at the same or higher reps, and calls any weight a PR when no such set exists ([PrDetector.kt:51](../../../forge-android/app/src/main/java/com/forge/app/domain/pr/PrDetector.kt#L51)). Nothing in the app shows the record that was beaten.
- **Why it matters:** The user can't tell a 0.5 kg PR from a 20 lb one, or a real record from "first time at 12+ reps". The app's biggest moment comes with no number to check.
- **Proposal:** Add `PrDetector.beaten(history, weightLb, reps): LoggedSet?`, which returns the competing max. Call it against the same running list `computePrFlags` builds (the prior frontier plus this session's earlier sets), so a record broken twice in one session points at the right set. On the PR row, replace the ghost line with `was 100 lb × 8` in muted mono, or `first at 12+ reps` when nothing competed, and add the same text to `rowDescription`.
- **Doctrine:** Fixes FAILURES "Verdict without a reading" and follows §4.9. The full-screen PR takeover stays removed (SETTLED): the reading lives inside the row. §5 keeps gold for the star and the row, and the new line is muted.

### TRL-09 · The numbers you read mid-set are the dimmest text on the card
accessibility · impact medium · effort S · Live session > exercise card, set rows, effort picker, rest controls

- **Now:** The pinned cue is muted@0.6, wrapped in ASCII `" … "` ([ExerciseCard.kt:235](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/ExerciseCard.kt#L235)). The form cue is @0.55 behind `ⓘ` ([ExerciseCard.kt:249](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/ExerciseCard.kt#L249)). Last time's set under each logged weight is @0.45 at 9sp ([SetRow.kt:410](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SetRow.kt#L410)). The RPE dash is @0.35, RIR labels are @0.6 at 8sp ([SetRow.kt:563](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SetRow.kt#L563)), and the rest total `/ 2:00` is @0.45 ([ExerciseCardComponents.kt:442](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/ExerciseCardComponents.kt#L442)). The rest dialog's `reset` and `done` are @0.6 ([RestTimerBubble.kt:375](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/RestTimerBubble.kt#L375)). AUDIT.md counts 227 off-ladder alphas app-wide. This finding is the subset a lifter actually reads mid-set, which that count doesn't rank.
- **Why it matters:** At arm's length under gym lighting, the hardest things to read are the cue you pinned ("elbows tucked") and the number you're trying to beat. At 0.45 they fall to about 3:1, below AA.
- **Proposal:** Snap each to the ladder. Content the user reads (pinned cue, last-time ghost, RIR, rest total) goes to muted 1.0 or the 0.65 floor, and the dialog controls to muted 1.0. Draw the pinned cue in §6's aside voice (bodySmall italic, muted, no quote marks), and the form cue without `ⓘ`.
- **Doctrine:** §5 alpha ladder, hard floor 0.65. FAILURES "Mute below the floor" says to cut or move, not fade. §8 bans decorative glyphs. The §5 placeholder exception covers text-field placeholders only.

### TRL-11 · The exercise chart draws a forecast the engine never computed
ui-polish · impact medium · effort S · Live session > tap the session strip > exercise chart sheet

- **Now:** `VolumeProjectionChart` extends the last segment's slope by two dashed accent points ([ExerciseChartSheet.kt:192](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/ExerciseChartSheet.kt#L192)), with a `┈ projected` legend in accent text ([ExerciseChartSheet.kt:120](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/ExerciseChartSheet.kt#L120)). The logged line is onBg rather than `primary`. Recent-session volumes are accent text ([ExerciseChartSheet.kt:174](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/ExerciseChartSheet.kt#L174)). The sheet paints `containerColor = background` ([ExerciseChartSheet.kt:72](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/ExerciseChartSheet.kt#L72)).
- **Why it matters:** A lifter checking history mid-session sees a forecast in the app's "important" colour. After a deload, the "projection" dives toward zero and reads as a prediction of collapse.
- **Proposal:** Drop the projection and its legend. Draw logged volume as the one series in `primary`. Draw the recent-session volumes in onBg. Set `containerColor = surface`. The finder suggested adding top weight as a second series; leave that out, because volume and load on one unlabelled axis would mislead, and the recent rows already carry `top 100 lb`.
- **Doctrine:** §12 bans ghost data. PRODUCT: "no coaching claims the engine does not actually compute". §10 sets the chart colours. §3 Modal uses a surface fill. §14 bans new accent text. The prior audit's 8-session PERSONAL BESTS window is a separate item.

### TRL-12 · Last session's note on an exercise is fetched but never shown
feature-gap · impact medium · effort S · Live session > exercise card

- **Now:** The builder loads the previous `LoggedExercise` and reads only its `difficulty` ([DayViewModelBuilders.kt:69](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/DayViewModelBuilders.kt#L69), [:126](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/DayViewModelBuilders.kt#L126)). The card's `note` is this session's only ([DayViewModelBuilders.kt:224](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/DayViewModelBuilders.kt#L224)), and the NOTE panel opens on a generic placeholder ([NoteField.kt:156](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/NoteField.kt#L156)). Old notes can be found through `NOTES_SEARCH` from Stats, but not from the card where they're needed. Only a pinned cue carries over between sessions.
- **Why it matters:** "Seat on 4, use the left cable" or "shoulder twinged at 30 kg", written last week, isn't there next week, which is exactly when it was written for.
- **Proposal:** Carry `prevLE.note` into `ExerciseUiState.lastNote`. When there's no pinned cue and this session's note is empty, show it in the pinned-cue slot as one muted italic aside, prefixed with its date in mono (`MAR 3 · seat on 4`). A pinned cue always takes that slot. The line is passive. (The finder's "Pin as cue promotes it" doesn't work: Pin acts on this session's note only.)
- **Doctrine:** §4.3 and FAILURES "Caption stack": it fills an existing slot and never stacks with the pinned cue. §6 aside voice. The data is already loaded, offline.

### TRL-10 · The swap picker never shows your own numbers on a move
feature-gap · impact medium · effort M · Live session > swap picker sheet

- **Now:** Each candidate row shows a glyph, a name and `muscleTarget` ([SwapPickerSheet.kt:244](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SwapPickerSheet.kt#L244)). Candidates are the equipment pool minus dislikes and same-day moves ([DayScreen.kt:225](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/DayScreen.kt#L225)). Whether you've done a move before, and at what load, only shows after you commit, when the card re-seeds from that move's history. Freestyle's start page already shows the last top set for recent moves (MAP FREESTYLE_LOG).
- **Why it matters:** Mid-session swaps happen because a station is taken, and the deciding question is "which of these do I know my weight on?". The picker can't answer that, so the lifter picks blind and then guesses a first-set load.
- **Proposal:** When the sheet opens, the VM builds `lastTopSetById` for the candidate ids (`WorkoutRepository.lastPerformanceSets` per id; the pool is 4 to 18 moves). Each row gets one right-meta reading on its name line, `70 lb × 10`, formatted through `WeightFormatter` or as a plate count. Moves never done carry nothing. Keep the best-first order and the armed lead row.
- **Doctrine:** §2① allows a row's right-meta when it's a reading. SETTLED's swap-picker entries removed prose (`why`, `whenToUse`) and ruled out a search field. This adds one number, no prose, no search and no new line. §12: rows without data carry no meta.

### TRL-14 · Plate math and the warm-up ladder for later lifts are built but cannot be reached
discoverability · impact medium · effort M · Live session > weighted exercise card

- **Now:** `PlateCalculatorDialog` and `WarmupSuggesterDialog` ([TrainingHelpers.kt:75](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/TrainingHelpers.kt#L75), [:199](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/TrainingHelpers.kt#L199)) render only on `ShowPlateCalculator` or `ShowWarmupSuggester` ([DayScreen.kt:310](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/DayScreen.kt#L310)). Nothing dispatches either, and the long-press quick-actions menu offers only skip and swap ([DayScreen.kt:275](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/DayScreen.kt#L275)). FEATURES.md lists "Plate calculator" as shipped, and MAP says later lifts get their ramp "on demand from `WarmupSuggesterDialog`" ([MAP.md:822](../../../.claude/design/MAP.md#L822)). The prior audit lists both events as dead with "delete, or wire". This is the case for wiring them.
- **Why it matters:** A barbell lifter does plate arithmetic between sets in an app that has the calculator built. The second and third heavy lifts get no warm-up ladder, even though the engine computes one.
- **Proposal:** On barbell lifts, show the per-side load as a passive mono reading under the weight field (`45 · 25 · 5 A SIDE`), recomputed from the typed value with `calculatePlates` and `WarmupEngine.barLoadFor`. It sits after the `N for PR` hint in the same supporting slot, so the field still carries one caption line. Retire the plate dialog once that ships. For exercises after the first, with no sets logged and a known working load, add `warm-up` in onBg with an accent `→` at the end of the plan line, opening the existing suggester.
- **Doctrine:** §2① lets a reading qualify an element. §3 Live is function-first. §2③: `→` for navigation, and §14 keeps the words onBg with only the glyph in accent. One link, no button wall. SETTLED's warm-up entry removed the fixed 40/60/80% suggester; this one already shares `WarmupEngine`.

### TRL-15 · Live sets cannot be tagged warm-up, drop or failure, and the RPE picker is drawn twice
consistency · impact medium · effort M · Live session > set row edit and effort picker

- **Now:** Freestyle's `FsTagTray` offers Normal / Warm-up / Drop set, AMRAP and To failure, plus RPE through `ForgeChoiceChip` ([FreestyleLogParts.kt:702](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogParts.kt#L702)). The live `SetRow` edits only weight and reps. Its RPE uses a separately drawn `InlineEffortPicker` with 8sp RIR labels and its own clear/close chrome ([SetRow.kt:494](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SetRow.kt#L494)). The VM handles `ToggleFailure`, `ToggleAmrap` and `SetSetType` ([DayExerciseHandlers.kt:196](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/DayExerciseHandlers.kt#L196)), but nothing in the UI dispatches them. `EffortModel` treats failure and drop sets as its strongest signal and excludes warm-ups ([EffortModel.kt:16](../../../forge-android/app/src/main/java/com/forge/app/domain/adapt/EffortModel.kt#L16)).
- **Why it matters:** A live set taken to failure can't say so, so the engine's strongest effort reading goes unused. A warm-up logged in the table counts toward the target and the effort read. The same RPE choice looks different depending on how the workout was started.
- **Proposal:** Extract `FsTagTray` to a gym-shared `SetTagTray` (the second use; §2⑥ says extract within the feature package). Render it under `SetRow`'s inline editor, and open it from the RPE pill in place of `InlineEffortPicker`. Wire the existing `SetSetType`, `ToggleFailure` and `ToggleAmrap`. TRL-03's input-row pill opens the same tray.
- **Doctrine:** §8 reuse, don't re-implement; §2⑥ extraction rule. A selection inside an edit state, not filled capsules. It lives in the row's existing edit state, so the untouchable screen gains no new surface.

### TRL-06 · Bodyweight lifts can never earn a PR
feature-gap · impact medium · effort L · Live session > bodyweight cards, session summary, PR counts

- **Now:** `PrDetector` returns false for any set without a weight, and its KDoc says bodyweight progression is "not surfaced as a PR" ([PrDetector.kt:15](../../../forge-android/app/src/main/java/com/forge/app/domain/pr/PrDetector.kt#L15)). The `N for PR` hint lives under the weight field, which a bodyweight card doesn't have. A green `+1 rep` delta against last session does show.
- **Why it matters:** Users training pull-ups, dips and push-ups (a large share of home lifters) never see a star, confetti, or NEW PR in the summary, however many reps they add.
- **Proposal:** Add an explicit bodyweight branch: more reps in one unassisted set than any prior bodyweight set of the exercise. The existing ★, gold row, confetti and summary count then fire unchanged, with a `13 for PR` hint under the reps field. Effort is L, because `PrDetector` also feeds the persisted `wasPr`/`prCount` ([WorkoutRepository.kt:234](../../../forge-android/app/src/main/java/com/forge/app/data/repo/WorkoutRepository.kt#L234)), the watch mirror, trophies and lifetime-PR milestones; audit each. Timed holds are left out (the finder's original included them): MAP keeps holds out of PR stats on purpose ([MAP.md:796](../../../.claude/design/MAP.md#L796)), and History already shows "Best 0:45".
- **Doctrine:** Reuses the one PR mark §5 reserves gold for. It isn't a new gamification surface (those are wait-listed in SETTLED), and it isn't a takeover. No plan doc covers it.

### TRL-07 · One PR, four different marks
consistency · impact low · effort S · Live session (set row, Up Next and done rows, input hint) and session summary
