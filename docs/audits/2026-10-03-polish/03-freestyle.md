# Freestyle logging, exercise browser, templates, notes search

Scope: the freestyle logger (start page, open/folded cards, entry slab, resume prompt), the exercise browser, the past-workout picker, notes search, the shared `ExerciseLibraryPicker` and the `DayLogSheet` (`ui/gym/freestyle/`, `ui/gym/notes/`, `ui/common/ExerciseLibraryPicker.kt`, `ui/common/DayLog.kt`). 17 raised, 17 kept (11 revised), 0 dropped.

The per-set loop rebuilt on 2026-09-26 holds up: the slab is seeded, the ledger is editable, deletes have Undo, the draft survives process death. The debt sits at the edges of a session, where freestyle is thinner than the live session that shares its archetype. A workout started from a template arrives already "done". A late log is always dated today. Rest is a count-up with no alert. A PR is never shown. There is nowhere to write a note. Around the logger, the pickers have drifted apart: there are three exercise pickers with different search rules, two "like" systems, two designs for one template row, and a notes search nothing links to.

## Findings

### FRE-01 · Repeat a workout logs the old workout as already done
ux-friction · impact high · effort M · Freestyle start page: REPEAT A WORKOUT rows and the Past workouts picker

- **Now:** `repeatWorkout` assigns the loaded session straight to `items` ([FreestyleLogScreen.kt:215](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogScreen.kt#L215)). `toItems` turns every past set into an `FsSet` in `FsExercise.sets` ([FreestyleLogModel.kt:314](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogModel.kt#L314)), the list whose KDoc says every set in it is a LOGGED set ([FreestyleLogModel.kt:18](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogModel.kt#L18)). So at 0:00 the header already counts them ([FreestyleLogParts.kt:115](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogParts.kt#L115)), and the bottom bar is armed as `Save workout · 18 sets` ([FreestyleLogScreen.kt:360](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogScreen.kt#L360)). The ledger rows look exactly like sets lifted today. The slab opens on `SET 07`, and Repeat all is hidden because the exercise "has sets" ([FreestyleLogParts.kt:313](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogParts.kt#L313)). The LAST exercise of the workout opens first ([FreestyleLogScreen.kt:224](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogScreen.kt#L224)). To actually train it, the user taps each old set, edits it and taps Update set, or deletes it.
- **Why it matters:** For a freestyle-mode lifter, repeating a known workout is the closest thing to a program. If they tap Save out of habit, or after doing half of it, a full copy of the old session is written dated today, and that copy inflates volume, the PR frontier, the streak and the heatmap. The one-tap Log set loop the rebuild was designed around doesn't exist on this path.
- **Proposal:** Seed the exercises in order with empty ledgers. Hold the chosen session's sets in a separate `templateSets` map on `FsLogState`, and do not write them into `lastTime`, so △ LAST and the start page's LAST readings keep comparing against the real latest performance. `FsLastTimeRow` shows those sets in the Last row's place. When the session isn't the latest performance, the row is labelled with its day (`AUG 12`) instead of `LAST`. `seedEntry` ([FreestyleLogModel.kt:124](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogModel.kt#L124)) reads the template's first set before last time's, so set 1 is still one tap away. Repeat all remains the one-tap way to log an exercise after the fact. Open the FIRST exercise. Persist the map in `FreestyleDraft` as an optional field, the way `"u"` was added ([FreestyleDraft.kt:65](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleDraft.kt#L65)). Update the row KDoc ("The whole row brings every set back", [FreestyleStartParts.kt:273](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleStartParts.kt#L273)).
- **Doctrine:** §3 Live/flow ([DESIGN.md:88](../../../.claude/DESIGN.md#L88)), function-first and one tap per set, is served better. No control is added: the existing Last row and Repeat all carry it, so there is no button wall. SETTLED's "Session detail's page-end actions removed" ([SETTLED.md:39](../../../.claude/design/SETTLED.md#L39)) was about a capsule on session detail, and this only changes what the start path seeds. Commit 9b283b1 wanted one tap to bring every set back, and that survives per exercise as Repeat all. Revised from the finder: a separate map, because overwriting `lastTime` would move the △ LAST bar to an older session.

### FRE-03 · A PR set in freestyle is never shown: no gold row, no confetti, no receipt
feature-gap · impact high · effort M · Freestyle set ledger and Save

- **Now:** The only mark a freestyle set can earn is the green `△ LAST` ([FreestyleLogParts.kt:437](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogParts.kt#L437)), which compares e1RM against last time's best set ([FreestyleLogModel.kt:106](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogModel.kt#L106)). All-time PRs are computed only inside save ([FreestyleLogViewModel.kt:187](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogViewModel.kt#L187), [WorkoutRepository.kt:222](../../../forge-android/app/src/main/java/com/forge/app/data/repo/WorkoutRepository.kt#L222)), after which `onSaved()` pops straight back ([FreestyleLogScreen.kt:318](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogScreen.kt#L318)). The live session paints the PR set in `ForgePrGold` with a ★ ([SetRow.kt:363](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SetRow.kt#L363)) and fires confetti ([DayScreen.kt:173](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/DayScreen.kt#L173)). The PR-milestone notification is posted only from `SessionSummarySheet` ([SessionSummarySheet.kt:92](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/components/SessionSummarySheet.kt#L92)), so a freestyle-only lifter never gets that one either.
- **Why it matters:** A freestyle-mode lifter never sees a PR happen. Their only logging flow is missing the app's main reward moment, and the PR turns up later only as a number in Stats.
- **Proposal:** When an exercise opens, load `repMaxFrontierForExercise(id, null)` and `hasHistoryForExercise` next to `lastSets` ([WorkoutRepository.kt:873](../../../forge-android/app/src/main/java/com/forge/app/data/repo/WorkoutRepository.kt#L873)). On Log set, run `PrDetector.isPr` against the frontier plus the sets already logged this session, and skip a first-ever exercise, the same rule `flagPrForLoggedExercise` applies. On a hit, paint that ledger reading in `ForgePrGold` with the ★, as `SetRow` does. On that row the ★ replaces △ LAST. Fire the `PR_OR_FINISH` haptic and `ConfettiOverlay`. As a second step, end a save that set a PR on the existing minimal `SessionSummarySheet`. Its `SessionSummary` can be built from the save payload: the coach line stays null because the coach is off in freestyle. That restores the milestone notification too. Use the same gold ★ the 02-train-logging pass settles on (TRL-07), so a PR has one mark app-wide.
- **Doctrine:** §3 Live/flow lists "confetti (PR only)" ([DESIGN.md:88](../../../.claude/DESIGN.md#L88)). §5 reserves PR gold for "PR star + gold set row" ([DESIGN.md:143](../../../.claude/DESIGN.md#L143)). SETTLED removed the full-screen PR takeover, leaving the PR moment as confetti plus the gold row ([SETTLED.md:81](../../../.claude/design/SETTLED.md#L81)), which is exactly this. It also removed session-summary extras, but the minimal sheet itself stays (MAP, Sheets). Revised from the finder: adds the first-exercise rule and the milestone notification, and makes the sheet a second step after the in-loop PR moment.

### FRE-04 · Rest is a count-up that scrolls away, with no countdown or alert
feature-gap · impact high · effort M · Freestyle log while resting between sets

- **Now:** Rest exists only as ` · REST m:ss` in the header eyebrow ([FreestyleLogParts.kt:104](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogParts.kt#L104)), lazy item 0. Opening any exercise scrolls its card to the top ([FreestyleLogScreen.kt:173](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogScreen.kt#L173)), so the reading is usually off screen while the user rests. The live session runs the shared `RestTimerController` on `SessionTimerHolder` ([SessionTimerHolder.kt:41](../../../forge-android/app/src/main/java/com/forge/app/service/wear/SessionTimerHolder.kt#L41)), draws `RestTimerBubble` ([DayScreen.kt:157](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/DayScreen.kt#L157)), and gets its pocket alert from `WorkoutSessionService`, fed by `bridge.notifyTimerDone()` ([DayViewModel.kt:186](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/DayViewModel.kt#L186)) once `startSessionService` has run ([DayViewModelRefresh.kt:226](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/train/DayViewModelRefresh.kt#L226)). Freestyle uses none of it.
- **Why it matters:** Every freestyle set is followed by a rest the user has to time with another app or by guessing. With the phone in a pocket, nothing tells them when to go.
- **Proposal:** Two steps. (S) Move the rest reading to the open card's slab eyebrow, where the thumb already is: `SET 03 · REST 1:42` in the row at [FreestyleLogParts.kt:486](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogParts.kt#L486). (M) On Log set, start the shared controller with the exercise's `restTimerOverrideSeconds` when one is set, otherwise `restCompoundSeconds` or `restIsolationSeconds`, chosen by `ExerciseTag.COMPOUND` on the def. Draw the existing `RestTimerBubble` over the log. For the alert to reach a pocket, the freestyle VM has to do what the day VM does: `bridge.startSession(...)` plus the foreground service while the log is open, call `notifyTimerDone` when the controller finishes, and stop both on save or leave. Decide in the same change whether the wrist mirrors this timer. `WearStatePublisher` will, while `WatchSessionMirror` deliberately keeps the watch idle for freestyle.
- **Doctrine:** §3 Live/flow names timers in its toolkit, and §9 allows timer-tick haptics. This reuses the one shared timer rather than re-rolling one (§8). The bubble is a session control, not a resident strip (§4.6). If the bubble's controls dialog is rebuilt (TRL-17 in 02-train-logging), freestyle inherits it. Revised from the finder: the alert needs the session bridge and service, not just the controller, and the per-exercise override is honoured.

### FRE-02 · A workout logged after the fact is always saved as today
feature-gap · impact high · effort M · Freestyle log header and save

- **Now:** The screen's KDoc says it logs a workout "as it happens or after the fact" ([FreestyleLogScreen.kt:70](../../../forge-android/app/src/main/java/com/forge/app/ui/gym/freestyle/FreestyleLogScreen.kt#L70)). The session start is `openedAtMs`, the moment the screen opened, and `saveFreestyleDraft` finishes it at `now` ([WorkoutRepository.kt:351](../../../forge-android/app/src/main/java/com/forge/app/data/repo/WorkoutRepository.kt#L351)). Every set is stamped `completedAt = clock.nowMs()` ([WorkoutRepository.kt:839](../../../forge-android/app/src/main/java/com/forge/app/data/repo/WorkoutRepository.kt#L839)). No gym surface takes a date: `DatePicker` appears only in cardio, the body logs, the photo gallery and vacation. Session detail is read only (SETTLED, 2026-09-26).
- **Why it matters:** Sunday's workout typed in on Monday lands on Monday. That moves the week strip, the streak, Stats' this-week figures, the heatmap day and the template's "when", and a freestyle-mode lifter has no way to correct it.
- **Proposal:** Turn the eyebrow's `OPEN WORKOUT` into a date capsule that defaults to today and opens a past-only date picker. The body logs already share `BodyLogDateCapsule` and `BodyLogDatePickerDialog` ([BodyweightLogSheet.kt:316](../../../forge-android/app/src/main/java/com/forge/app/ui/profile/BodyweightLogSheet.kt#L316), [:370](../../../forge-android/app/src/main/java/com/forge/app/ui/profile/BodyweightLogSheet.kt#L370)), and cardio keeps its own copy ([CardioLogSheetSections.kt:197](../../../forge-android/app/src/main/java/com/forge/app/ui/cardio/components/CardioLogSheetSections.kt#L197)), so promote the pair to `ui/common` in the same change. When a past day is picked, drop the running clock and the rest readout and show a duration stepper in minutes. Save passes `startedAt = picked day + time` and `finishedAt = startedAt + duration`: `saveFreestyleDraft` gains an `endMs` that it hands to `finishInTransaction`, and `logSet` takes a `completedAt` so the sets land on the same day (otherwise the Health Connect mirror and the set timestamps still say today).
- **Doctrine:** §2⑥ ([DESIGN.md:74](../../../.claude/DESIGN.md#L74)): promote on the third use, don't write a fourth copy. §13: hot-path numbers are steppers, which covers duration. Not on SETTLED's removals list: "Log again today" re-logged an OLD session, and this dates a NEW one. The live case keeps its clock. Revised from the finder: names the existing capsule to reuse and the per-set timestamp the save also has to carry.

The card's copy is a question plus mechanics: "Do you want to create it as a custom exercise? You can log it just like any other move."
- **Why it matters:** A custom ring muscle-up or L-sit has to be logged with a weight field, so it never gets the hold timer. A typo like "Sled Psuh" stays in the browser and its search forever. Since the 2026-09-26 fix, browser search includes custom moves, so typos now resurface more often.

Add an optional `unit` to `CustomExerciseDef`'s JSON: older builds' tolerant parse ignores the extra key, so `SCHEMA` can stay 1. Build `FsExercise.bodyweight` and `timed` from it, and pass it as `swappedUnit` on save. List the registry's moves in Settings → Exercise likes' Custom scope next to the program-editor ones, each with a Remove action through `SnackbarController.showUndo` that unregisters the move; history rows keep their `swapped_name`. Cut the card's second sentence and keep `No exercises match "x"` plus the `Create "x"` capsule.
- **Doctrine:** `ForgeSlidingSegments` is the kit's one-of-three control (§8). §12 undo over confirm: a removal that can be undone gets no dialog. §4.3 cuts mechanics narration, and §11 prefers a statement to a question. AUDIT_DEFERRED M9 is about a template carrying a unit it already has, not about choosing one at creation. Revised from the finder: Settings never listed these moves, so removal has to come with listing them there.

### FRE-10 · The browser star is a second "like" system, named three ways

Revised from the finder: Settings itself says "Preferred", the ★ collides with the PR mark, and the merge has to respect dislikes. Impact lowered to low.
