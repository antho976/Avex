# Avex 1.0 — launch trailer

108 seconds, 1920×1080, 60 fps, with an original score and sound effects synthesised here. One HTML
page (`index.html`) where every frame is a pure function of time (`window.__seek(t)`), so the
browser preview and the rendered file cannot disagree. No Remotion, no licensed audio.

```
python3 tools/sfx.py audio/sfx                   # the ten effects, each checked against RULES.md limits
python3 tools/music.py out/score.wav             # the score, 100 BPM, printed levels per stem/band/bar
node tools/render.mjs cues out/cues.json         # the cues and cuts the film declares
python3 tools/mixdown.py out/score.wav out/cues.json out/mix.wav   # −16 LUFS, peak ≤ −2 dBFS
ffmpeg -i out/mix.wav -c:a libmp3lame -b:a 192k audio/trailer-mix.mp3   # for the in-browser player
node tools/render.mjs video out/picture.mp4 60   # every frame through headless Chromium → x264
ffmpeg -i out/picture.mp4 -i out/mix.wav -c:v copy -c:a aac -b:a 256k -shortest out/avex-1.0-trailer.mp4
python3 tools/synccheck.py out/avex-1.0-trailer.mp4 out/cues.json   # cuts, kicks and cues vs the grid
node tools/render.mjs stills out/stills 14.0 28.0   # single frames, for checking a moment
```

Needs Node ≥ 22 (built-in `WebSocket`), `/usr/bin/chromium`, ffmpeg and numpy. `out/` is ignored.
Read `remotion-release/RULES.md` before changing anything: this cut follows it.

## Sync

The picture and the score are written on one grid: 100 BPM, so a beat is 0.6 s = 36 frames and a
bar is 2.4 s = 144 frames. Every scene starts on a bar line, every push lands on its downbeat, every
entrance starts 0.1 s before its cue, and the cue list is read out of the page rather than typed.
`synccheck.py` measures the delivered file: the kick drum against the bar grid and each effect
against its frame.
